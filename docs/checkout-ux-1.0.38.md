# Checkout UX 1.0.38

The ammunition destination dropdown saves on change. Standard checkout switches between the native shipping form and dealer selection in place, without reloading the page. Ammo-only carts use the server-projected cart state rules to update the UI immediately; Magento verifies and persists the destination in the background. Rapid selections are serialized and coalesced so an older request cannot overwrite the final choice. Failed saves and unresolved destinations block checkout. Native shipping submission and order placement retain their server-side routing guards.

The customer shipping address and billing data survive destination changes. A change invalidates the selected dealer and old shipping rates. Native address-book entries remain available for home delivery, and dealer addresses are hidden from the home address list. The notice describes dealer delivery without calling ammunition a firearm.

Home-address snapshots capture the native form even while Magento's quote address is still pending. Snapshots are independent of the mutable checkout provider and exclude dealer metadata. Dealer selection binds the complete address to the native checkout provider in one operation, retaining the FFL attributes during delayed rate calculation and native validation.

The shared dealer iframe now opens in a centered popup matching WooCommerce: 70% viewport width and height on desktop, 96% width and 90% height at 800px and below, a 6px radius, the same shadow and 50% black overlay, and an iframe filling the modal without Magento header/footer padding. The styles are scoped to the dealer popup so native Magento address and confirmation modals retain their controls.
